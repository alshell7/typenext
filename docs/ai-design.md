# AI suggestion design

TypeNext helps the writer continue at the cursor. It does not replace the draft, rewrite the writer’s argument, or automatically ask a cloud model to take over. Routine suggestions default to **Local**. The writer can explicitly activate a hosted provider with **Use continuously**; automatic and manual requests then use that provider until the writer switches back. This intentional selection persists, while old notebooks without the activation flag migrate to local. The service never retries a failed local request with an external provider.

With no model selected, **Local recall** first looks for exact continuations in enabled references or the note's own writing. When there is no matching phrase, lightweight **Writing starters** offer up to three optional ways into a line. They use bounded text from the note's objective, background, title, and current writing. They are deterministic English prompts, labelled separately from inference, and do not invent factual claims. Blank notes and paragraph starts need no attachments. Unsupported language, unknown word fragments, code, and unproven bridges into existing same-line text can still produce no starter.

With a local server selected, TypeNext calls a loopback server using the note’s title, objective, writing brief, relevant reference passages, and text before and after the cursor. References are optional; a meaningful title can also guide a blank note. A server error remains visible; it does not trigger a cloud fallback. An empty local model response may use offline recall or starters instead.

Automatic suggestions remain inline. Ctrl/Command + Space opens a small cursor-anchored list; arrow keys preview a choice while focus stays in the editor, Enter or Tab accepts, and Escape dismisses. Previewing never changes the document. Typing, moving the cursor, changing notes, composition, or leaving the editor invalidates the menu and any pending request. The menu follows the keyboard and active-descendant approach documented in the [WAI-ARIA autocomplete guidance](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/), while retaining the editor's multiline textbox semantics. Reduced motion disables its brief entrance transition.

For an intentionally selected external chat provider, each Ctrl/Command + Space request bypasses the inline completion cache and makes one fresh generation call. The prompt asks for a JSON list of up to three distinct insertions at the same cursor; no per-choice fan-out or provider retry occurs. Each choice receives the ordinary suffix/whitespace sanitizer and short-insertion budget. The aggregate response is capped at 384 output tokens and 12,000 characters; parsing examines at most 12 list entries and retains at most three distinct, valid choices. Invalid JSON produces a visible error. Ordinary automatic continuations still request one plain insertion. Local engines and native FIM retain their existing completion/recall/starter path, and moving among menu choices makes no additional model call.

The editor accepts an AI suggestion only on an explicit acceptance action. Ghost text is outside the saved document. Abort signals and the editor’s note/document/cursor revision checks keep old results out of a changed draft. The service holds at most 24 cached inline completions against the full bounded prompt, selected model, provider and generation settings; cache hits expire after 30 seconds. Fresh external manual choices neither read nor write that cache. Only one generation request can be active in the service, across built-in, local-server and hosted inference. Provider discovery uses bounded model-list GET requests. Overlapping direct calls receive a busy error rather than creating an unbounded queue; the editor separately schedules its latest request. API keys are obtained from the native secret service, are excluded from prompts and notes, and are not saved in browser localStorage.

Adaptive length follows the cursor. A missing word or a phrase inside existing text gets a small budget; an unfinished sentence gets a brief continuation; an empty paragraph can get one short sentence. Short and Sentence are explicit alternatives. The configured max-token value is an upper bound. Output handling preserves leading whitespace, punctuation, case and partial-word insertions, removes echoed suffix text, and clips verbosity. A small model can still offer an unhelpful insertion; rejection is always available, and the app never accepts a suggestion on the writer’s behalf.

Context retrieval uses a self-contained BM25 index over the current note's resolved sources: attached context packages plus any direct references. Unicode letters, numbers and combining marks are retained; CJK character bigrams handle phrases without spaces. Extracted snapshots are stored once in the context library and are not reparsed during completion. Source indexes are reused across writing edits and rebuilt when indexed source data changes. Each index covers at most one million characters, 300,000 per source, with at most two million indexed characters across the entire memory cache and a secondary limit of 12 small-note entries. The cache retains only bounded indexed source snapshots; truncated excerpts are copied to avoid keeping an entire large linked note alive. Chunks contain up to 1,400 characters with overlap. Retrieval returns up to eight passages with a 6,000-character total cap; the model prompt uses at most 3,600 reference characters, 5,000 prefix characters, 1,500 suffix characters, an 800-character objective and a 1,200-character brief. Character limits are approximate context budgets, not tokenizer-specific token counts. Measurements and regression coverage are recorded in [the service resource audit](services-resource-audit.md).

The same retrieval path is used for automatic inline suggestions and the manual menu, before dispatch to embedded SmolLM, local chat, native FIM, OpenAI, OpenRouter, Anthropic or a custom endpoint. Only sources resolved from the current note are eligible; the rest of the context library stays out of the request. The current line near the cursor and nearby suffix are scored separately from the broader objective/brief. Cursor matches take precedence; when none match, ordinary background ranking supplies context. This prevents a long writing brief from crowding out the particular fact being completed. Interactive context search keeps its ordinary query ranking.

The built-in model receives at most two 320-character excerpts, with a separate 768-token input ceiling. A literal match for the current prose fragment selects its containing reference line within the retrieved chunk instead of blindly sending the first 320 characters. Other excerpts retain the bounded prefix; intentional code context is unchanged. The token ceiling can drop references to preserve the actual cursor. Server models receive up to four retrieved passages, capped at 3,600 reference characters in total. BM25 is lexical retrieval, not semantic embeddings, and supplying relevant text is not a guarantee that a model will obey or reproduce it correctly.

**Try a sample** installs an optional fictional Bramble House note, a details package with three Markdown/text sources, and a separate voice package. It uses normal notes, package attachments, retrieval and persistence; it has no special suggestion engine or predetermined model responses. Installation does not change model selection, permissions, autosave or existing writing. Reopening preserves edits and detachment. The shipped [source files](../examples/bramble-house) are also available as a ZIP; rebuild it after changing the files with `node scripts/build-demo.mjs`. Unit tests compare the archive's bytes with the app's source material.

[Orama JS](https://github.com/oramasearch/orama) is a compatible future retrieval option under Apache-2.0. Its [default scoring algorithm is already BM25](https://docs.orama.com/docs/orama-js/search/changing-default-search-algorithm), so Orama and BM25 are not competing architectures. It also supports vector and hybrid search. [bm25s](https://github.com/xhluca/bm25s) is MIT and uses Python/NumPy; embedding that runtime adds packaging work to a small desktop app. The initial local index avoids both a Python runtime and an embedding model. A semantic index can be added later if measured recall warrants it.

Text and Markdown import use UTF-8 locally. [PDF.js](https://github.com/mozilla/pdf.js) (Apache-2.0) streams PDF text with page markers; its worker is packaged with the app and loaded only when a PDF is imported. Page resources are released on success, failure and cancellation, and the loading task is destroyed afterward. [Mammoth](https://github.com/mwilliamson/mammoth.js) (BSD-2-Clause) extracts DOCX as plain text, avoiding rendered HTML from a document. Before Mammoth runs, lazy [fflate](https://github.com/101arrowz/fflate) (MIT, pinned 0.8.3) streaming inflation verifies actual ZIP output rather than trusting declared sizes: at most 2,048 entries, 32 MiB total expansion and 4 MiB XML/relationship data. Small compressed pushes bound temporary inflation work and periodically yield for cancellation. Context files are limited to 12 MiB, 300,000 extracted characters, and 150 PDF pages; oversized plaintext is rejected before reading. Only one source import can run at a time. File and website import accept AbortSignal; no cancelled result is attached. Password-protected PDFs, scanned PDFs without selectable text, legacy `.doc`, unsupported files and invalid UTF-8 have explicit messages. The app does not silently upload those files. [Unstructured](https://docs.unstructured.io/open-source/core-functionality/partitioning) can support a future opt-in OCR/legacy-document path, but is not wired into this importer. Its local `.doc` path requires LibreOffice conversion.

The PDF integration uses PDF.js 6.2.108, patched for [GHSA-hq66-cqwq-w95j](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j). The compatibility build and its matching worker stay lazy to accommodate system webviews without the newest JavaScript helpers. Text extraction passes local bytes to `getDocument`, disables worker fetching and font-face loading, and disables image-decoding WASM. It never creates a PDF viewer or scripting manager and never runs PDF actions. The advisory's `enableScripting` option belongs to viewer scripting; it is not an extraction API option. Keep the parser and worker on the same patched package version.

Website import is a deliberate attachment action. Direct import fetches the selected public URL through the native HTTP service, extracts article text with [Mozilla Readability](https://github.com/mozilla/readability) (Apache-2.0), and stores the result locally. It does not execute page scripts. Dynamic websites can use the separately selected [Firecrawl scrape endpoint](https://docs.firecrawl.dev/features/scrape): `/v2/scrape` with Markdown and main-content extraction. Only that selected URL is submitted with the configured Firecrawl key. Direct failures do not silently switch to Firecrawl. On desktop, source fetches use `publicOnly` to reject private resolved addresses, pin DNS, and repeat the guard on redirects. The browser preview applies literal URL checks and browser network/CORS rules, but cannot enforce DNS pinning. Website fetching is separate from model requests, and no website is refetched on each suggestion.

Chat requests carry context as JSON. The system instruction describes reference text, filenames and URLs as untrusted data, instructs the model to ignore embedded instructions, and requests only the insertion or manual list of alternative insertions. References cannot trigger tool calls or execute actions. The note objective and brief describe the writer’s intent. If there is no meaningful continuation, the model may return an empty response or empty choice list. Temperature is a user-controlled sampling parameter; it does not guarantee factual accuracy or preserve intent by itself.

OpenRouter short insertions request `reasoning: { enabled: false, exclude: true }`. Its [reasoning documentation](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens) explains that hidden thinking usually shares the output-token budget; a tiny budget can otherwise produce no visible completion. Prefer instruction models that permit reasoning to be disabled. Models with mandatory reasoning may reject this setting and are poor choices for short, fast suggestions. This adjustment applies only to OpenRouter and does not add cloud traffic to ordinary suggestions.

Native FIM is a trained capability, not simply adding special tokens to any chat model. Prefix/suffix prompting gives general instruction models a compatible prose path. Native FIM models depend on their own tokenizer/training templates, and their handling of extra context differs. Test short suggestions on the writer’s actual prose, including partial words, existing suffixes, multilingual text, Markdown structures, and misleading source instructions.

[Needle 3](https://github.com/cactus-compute/needle) is now an Apache-2.0 structured tool/extraction model, with browser WASM and Windows/macOS assets. Its JSON-focused behavior does not fit general prose FIM. [Whistle](https://cactuscompute.com/blog/whistle) is the relevant Cactus speech option: 16.9 MB CPU transcription weights, a shared WASM engine, bounded clips and seven documented languages. These current products have distinct licensing and deployment details from older general Cactus Engine guidance. See [the fresh research and built-in smoke evidence](builtin-models.md) for the practical fit and telemetry distinction.

Primary-source research was checked on 5 October 2026. Models and runtime interfaces should be pinned and checked again before packaging releases. An authorized [live OpenRouter smoke check](testing.md) verified a free-model suggestion, cursor insertion and Tab acceptance using synthetic writing. Separate [built-in CPU samples](builtin-models.md) verify real local inference while exposing weak objective/suffix handling and material runtime memory use. Neither smoke establishes broad writing quality, other hosted-provider performance or native FIM. The [Colab FIM recipe](fim-training.md) is syntax/preparation-tested but has not been trained, exported or quality-evaluated.

## Reusable context and explicit inference modes

Canonical reference snapshots live in `workspace.contextLibrary`. Named packages in `workspace.contextPackages` hold source IDs; each note attaches packages through `contextPackageIds`. A package may contain several files, folder snapshots, websites and live note links, and several notes can reuse it without copying source text. Editing a shared package changes the references seen by its attached notes; detaching it affects only that note. Sources shared across attached packages are deduplicated before retrieval. Existing direct references retain their text-empty `libraryId` links and per-note enabled flags. Earlier libraries migrate into named “Saved references” packages without automatically attaching a package or changing a note's references. Colliding legacy source IDs are preserved safely.

Linked notes resolve their current title and own writing only, so cycles never recurse and a note cannot use itself as context. File, website and folder imports are snapshots rather than filesystem watchers or automatic web refreshes. A folder import accepts up to 256 supported files per batch. The library retains at most 2,048 entries; the workspace supports up to 256 packages, 256 sources per package, and 64 attached packages per note. New attachments and package changes are preflighted against 256 distinct resolved sources, two million enabled context characters per note, and the 64 MiB workspace limit. The BM25 and prompt budgets above remain smaller than these storage limits. Existing legacy sources that cannot be promoted at the library limit remain intact.

The actual BM25 index remains bounded to enabled resolved context. The note context panel has an explicit search that shows matching passages and invalidates displayed results when source text or inclusion changes. Retrieval plus bounded passages in a model prompt is the implemented RAG path; it does not use a vector database or embeddings.

External activation uses the persisted `externalAutoEnabled` flag. Merely configuring a key/model does not activate it. The chosen provider and model are visible near the editor, with a direct route back to local. Preferences preserve other provider profiles. System instructions are bounded to 8,000 UTF-8 bytes and participate in completion cache invalidation; the tiny built-in model uses a shorter prompt budget. Model catalogs use authenticated GET requests, including Anthropic pagination; OpenRouter's free filter uses declared prompt, completion and request prices.

The optional SmolLM2 ONNX worker is isolated from the editor. Download initiation is explicit, assets are revision-pinned and SHA-256 checked before caching, runtime files are self-hosted, generation/cache reload cannot fetch model data, and idle unloading releases worker memory. No model weights enter notebook snapshots. See the built-in model research and smoke evidence for quality and platform limits; loading a model is not evidence of useful prose.

## Inline dictation

Whistle is an optional, separately downloaded local speech model. The microphone button or Ctrl/Command + Shift + D starts recording at an empty selection; pressing the shortcut again or Stop ends the clip. Capture stops automatically after 30 seconds. A small marker follows the recording position through typing edits, while the writer can keep typing or move the cursor elsewhere. AI suggestions pause during capture/transcription. A successful transcript is inserted at that mapped position as one undoable edit; the usual autosave and automatic-suggestion scheduling then run, when enabled. There is no review modal or extra confirmation. AI suggestion acceptance remains explicit.

Microphone setup enumerates local input metadata without requesting permission. Only the explicit “Allow and refresh microphones” action opens temporary access to read device labels; that stream stops as soon as enumeration finishes, or after its three-second enumeration deadline. Recording requires its own gesture. System default follows the operating system; a selected device uses an exact constraint and reports an unavailable input rather than changing microphones. The optional level meter adds RMS values to the existing approximately five-hertz duration messages, with no UI polling or extra audio buffer.

Escape, cancellation, hiding the document and changing notes stop recording and abort decoding. Permission granted after cancellation immediately has its tracks stopped. Late transcripts cannot enter another note. Captured PCM is bounded to 480,000 mono Float32 samples and is wiped after processing; decoded text is capped at 12,000 characters. If the insertion position was deleted or the note is full, the transcript remains in an editable recovery field with Insert at cursor and Discard transcript actions. Speech recognition sends no audio or writing to a service. Once inserted, dictated text follows the same intentionally selected suggestion provider as typed text; an active external model can receive its bounded writing context. See [built-in model provenance and smoke evidence](builtin-models.md).
