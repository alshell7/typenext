# AI suggestion design

TypeNext helps the writer continue at the cursor. It does not replace the draft, rewrite the writer’s argument, or automatically ask a cloud model to take over. Routine automatic suggestions and the normal manual shortcut use **Local**. A cloud or remote custom request is a separate, explicit action. The service never retries a failed local request with an external provider.

With no model selected, **Local recall** first looks for exact continuations in enabled references or the note's own writing. When there is no matching phrase, lightweight **Writing starters** offer up to three optional ways into a line. They use bounded text from the note's objective, background, title, and current writing. They are deterministic English prompts, labelled separately from inference, and do not invent factual claims. Blank notes and paragraph starts need no attachments. Unsupported language, unknown word fragments, code, and unproven bridges into existing same-line text can still produce no starter.

With a model selected, TypeNext calls a loopback server using the note’s title, objective, writing brief, relevant reference passages, and text before and after the cursor. References are optional; a meaningful title can also guide a blank note. A server error remains visible; it does not trigger a cloud fallback. An empty local model response may use offline recall or starters instead.

Automatic suggestions remain inline. Ctrl/Command + Space opens a small cursor-anchored list; arrow keys preview a choice while focus stays in the editor, Enter or Tab accepts, and Escape dismisses. Previewing never changes the document. Typing, moving the cursor, changing notes, composition, or leaving the editor invalidates the menu and any pending request. The menu follows the keyboard and active-descendant approach documented in the [WAI-ARIA autocomplete guidance](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/), while retaining the editor's multiline textbox semantics. Reduced motion disables its brief entrance transition.

The editor accepts a suggestion only on an explicit acceptance action. Ghost text is outside the saved document. Abort signals and the editor’s note/document/cursor revision checks keep old results out of a changed draft. The service holds at most 24 cached completions against the full bounded prompt, selected model, provider and generation settings; cache hits expire after 30 seconds. Only one generation request can be active in the service, including an Anthropic connection check. Overlapping direct calls receive a busy error rather than creating an unbounded queue; the editor separately schedules its latest request. API keys are obtained from the native secret service, are excluded from prompts and notes, and are not saved in browser localStorage.

Adaptive length follows the cursor. A missing word or a phrase inside existing text gets a small budget; an unfinished sentence gets a brief continuation; an empty paragraph can get one short sentence. Short and Sentence are explicit alternatives. The configured max-token value is an upper bound. Output handling preserves leading whitespace, punctuation, case and partial-word insertions, removes echoed suffix text, and clips verbosity. A small model can still offer an unhelpful insertion; rejection is always available, and the app never accepts a suggestion on the writer’s behalf.

Context retrieval uses a self-contained BM25 index over enabled attachments in the current note. Unicode letters, numbers and combining marks are retained; CJK character bigrams handle phrases without spaces. Extracted text is stored on the note and is not reparsed during completion. Source indexes are reused across writing edits and rebuilt when indexed source data changes. Each index covers at most one million characters, 300,000 per source, with at most two million indexed characters across the entire memory cache and a secondary limit of 12 small-note entries. The cache retains only bounded indexed source snapshots; truncated excerpts are copied to avoid keeping an entire large linked note alive. Chunks contain up to 1,400 characters with overlap. Retrieval returns up to eight passages with a 6,000-character total cap; the model prompt uses at most 3,600 reference characters, 5,000 prefix characters, 1,500 suffix characters, an 800-character objective and a 1,200-character brief. Character limits are approximate context budgets, not tokenizer-specific token counts. Measurements and regression coverage are recorded in [the service resource audit](services-resource-audit.md).

[Orama JS](https://github.com/oramasearch/orama) is a compatible future retrieval option under Apache-2.0. Its [default scoring algorithm is already BM25](https://docs.orama.com/docs/orama-js/search/changing-default-search-algorithm), so Orama and BM25 are not competing architectures. It also supports vector and hybrid search. [bm25s](https://github.com/xhluca/bm25s) is MIT and uses Python/NumPy; embedding that runtime adds packaging work to a small desktop app. The initial local index avoids both a Python runtime and an embedding model. A semantic index can be added later if measured recall warrants it.

Text and Markdown import use UTF-8 locally. [PDF.js](https://github.com/mozilla/pdf.js) (Apache-2.0) streams PDF text with page markers; its worker is packaged with the app and loaded only when a PDF is imported. Page resources are released on success, failure and cancellation, and the loading task is destroyed afterward. [Mammoth](https://github.com/mwilliamson/mammoth.js) (BSD-2-Clause) extracts DOCX as plain text, avoiding rendered HTML from a document. Before Mammoth runs, lazy [fflate](https://github.com/101arrowz/fflate) (MIT, pinned 0.8.3) streaming inflation verifies actual ZIP output rather than trusting declared sizes: at most 2,048 entries, 32 MiB total expansion and 4 MiB XML/relationship data. Small compressed pushes bound temporary inflation work and periodically yield for cancellation. Context files are limited to 12 MiB, 300,000 extracted characters, and 150 PDF pages; oversized plaintext is rejected before reading. Only one source import can run at a time. File and website import accept AbortSignal; no cancelled result is attached. Password-protected PDFs, scanned PDFs without selectable text, legacy `.doc`, unsupported files and invalid UTF-8 have explicit messages. The app does not silently upload those files. [Unstructured](https://docs.unstructured.io/open-source/core-functionality/partitioning) can support a future opt-in OCR/legacy-document path, but is not wired into this importer. Its local `.doc` path requires LibreOffice conversion.

The PDF integration uses PDF.js 6.2.108, patched for [GHSA-hq66-cqwq-w95j](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j). The compatibility build and its matching worker stay lazy to accommodate system webviews without the newest JavaScript helpers. Text extraction passes local bytes to `getDocument`, disables worker fetching and font-face loading, and disables image-decoding WASM. It never creates a PDF viewer or scripting manager and never runs PDF actions. The advisory's `enableScripting` option belongs to viewer scripting; it is not an extraction API option. Keep the parser and worker on the same patched package version.

Website import is a deliberate attachment action. Direct import fetches the selected public URL through the native HTTP service, extracts article text with [Mozilla Readability](https://github.com/mozilla/readability) (Apache-2.0), and stores the result locally. It does not execute page scripts. Dynamic websites can use the separately selected [Firecrawl scrape endpoint](https://docs.firecrawl.dev/features/scrape): `/v2/scrape` with Markdown and main-content extraction. Only that selected URL is submitted with the configured Firecrawl key. Direct failures do not silently switch to Firecrawl. On desktop, source fetches use `publicOnly` to reject private resolved addresses, pin DNS, and repeat the guard on redirects. The browser preview applies literal URL checks and browser network/CORS rules, but cannot enforce DNS pinning. Website fetching is separate from model requests, and no website is refetched on each suggestion.

Chat requests carry context as JSON. The system instruction describes reference text, filenames and URLs as untrusted data, instructs the model to ignore embedded instructions, and requests only the insertion. References cannot trigger tool calls or execute actions. The note objective and brief describe the writer’s intent. If there is no meaningful continuation, the model may return an empty response. Temperature is a user-controlled sampling parameter; it does not guarantee factual accuracy or preserve intent by itself.

OpenRouter short insertions request `reasoning: { enabled: false, exclude: true }`. Its [reasoning documentation](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens) explains that hidden thinking usually shares the output-token budget; a tiny budget can otherwise produce no visible completion. Prefer instruction models that permit reasoning to be disabled. Models with mandatory reasoning may reject this setting and are poor choices for short, fast suggestions. This adjustment applies only to OpenRouter and does not add cloud traffic to ordinary suggestions.

The first release connects to user-managed local servers; it does not bundle or automatically download model weights. A later embedded runtime should favor a pinned llama.cpp sidecar with optional, verified model downloads. [ONNX Runtime GenAI](https://github.com/microsoft/onnxruntime-genai) also supports Windows and Mac and manages tokenization, generation and KV caches. It is useful for a selected, tested model/backend combination, especially Windows hardware acceleration, but requires ONNX conversion and execution-provider packaging. Its current matrix does not list Metal.

Native FIM is a trained capability, not simply adding special tokens to any chat model. Prefix/suffix prompting gives general instruction models a compatible prose path. Native FIM models depend on their own tokenizer/training templates, and their handling of extra context differs. Test short suggestions on the writer’s actual prose, including partial words, existing suffixes, multilingual text, Markdown structures, and misleading source instructions.

[Cactus Engine](https://cactuscompute.com/engine) is an optional local-server candidate, not a required runtime. Its documentation emphasizes mobile, macOS and wearables. The current [Cactus license](https://github.com/cactus-compute/cactus/blob/main/LICENSE) has organization funding/revenue and user-category conditions. The separate [Needle](https://www.cactuscompute.com/needle) product emphasizes automation, extraction and embeddings and trades away general chat capacity; it should not be chosen for prose merely because it is tiny. [LFM2.5-1.2B-Instruct](https://huggingface.co/LiquidAI/LFM2.5-1.2B-Instruct) is another interesting low-memory CPU candidate, but its [custom license](https://huggingface.co/LiquidAI/LFM2.5-1.2B-Instruct/raw/main/LICENSE) includes commercial revenue conditions. These choices remain optional so the app’s open-source usability does not depend on those eligibility rules.

Primary-source research was checked on 5 October 2026. Models and runtime interfaces should be pinned and checked again before packaging releases. A later authorized [live OpenRouter smoke check](testing.md) verified an explicit free-model suggestion, cursor insertion and Tab acceptance using synthetic writing. Local runtime hardware performance, wider prose quality, other hosted providers and native FIM still require real-model evaluation; none of those are implied by that one smoke check.
