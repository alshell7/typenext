# Service resource audit, 2026-10-05

Synthetic measurements identified two useful changes: limit total cached reference text rather than retaining twelve large indexes, and read a bounded first line rather than split a whole note to infer its objective. Import guards now also bound actual Word archive expansion, release PDF resources on errors and cancellation, and permit only one active extraction. No model, hosted endpoint, notebook or credential file was used in this audit.

The measurements below compare fresh Node 24.17.0 processes on the same Windows x86_64 / Ryzen 7 7840U host. The retrieval script imports the actual TypeScript service. The completion/import script bundles the actual services with a fake in-memory native transport; it does not issue network requests. Garbage collection was explicitly requested for retained-heap readings. These are diagnostic observations, not total desktop-app RAM measurements, model inference timings or repeated statistical benchmarks.

A 5,243-byte forged Word archive declared ten XML bytes but expanded to 5,242,880 bytes. Actual streaming verification rejected it in 24.569 ms before Mammoth was invoked. This is a single diagnostic sample; it is not an import performance benchmark. Unit regressions also cover a small declared-size mismatch, invalid compressed data, cancellation during validation, failed PDF extraction, an oversized PDF text stream, and a valid Unicode text source at the character limit.

The reproducible scripts and JSON reports are ignored local artifacts under `artifacts/service-benchmark/`: `retrieval.mjs`, `services.mjs`, `baseline.json`, `final.json`, `services-baseline.json` and `services-final.json`. Inputs are synthetic. Re-running them uses the installed development dependencies and no network.

The retrieval cache holds at most 2,000,000 indexed characters across at most 12 entries, with 1,000,000 characters per note and 300,000 per source. Its snapshots include only the indexed portion, and a truncated string is copied so it cannot retain a much larger original. Source validation examines at most 256 entries and preserves invalidation when text changes without changing length. BM25 work remains bounded to 128 query terms and bounded chunks; output remains at most eight chunks and 6,000 characters. The model prompt has a smaller 3,600-character reference budget.

The completion cache holds at most 24 bounded prompt/result entries, with 30-second cache-hit validity. Prefix and suffix work is bounded to 5,000 and 1,500 characters. Endpoint/model configuration and unexpected raw model output have explicit size bounds. One generation can run at a time, including the minimal Anthropic connection check; the slot is released after success, failure or cancellation. An extra caller receives a clear busy error instead of building a queue or silently choosing another provider.

Source import accepts `AbortSignal` and allows one active file or website extraction, without a waiting queue. Plaintext byte limits are checked before reads. PDF text arrives in streamed chunks, stops at 300,000 retained characters, and cleans both the page and loading task on every exit. The PDF worker remains lazy and local. Direct HTML imports reject responses above 2,000,000 characters and excessive element counts before constructing a DOM. Network response limits remain the responsibility of the native broker.

DOCX validation first checks ZIP structure and declared budgets, then counts actual inflated bytes without retaining the decompressed parts. It permits stored and deflated entries, at most 2,048 entries, 32 MiB total output and 4 MiB XML/relationship output. Declared/actual size mismatches are rejected. Deflated input is pushed in 64-byte pieces, with periodic event-loop yields and abort checks; this avoids sending the entire compressed archive into an inflater before checking output. Only after validation does Mammoth read the document. Its parsing phase is checked before and after completion; cancellation cannot interrupt every synchronous parser instruction. These safeguards bound supported inputs and concurrent work rather than claiming a universal heap ceiling for third-party parsers.

[fflate 0.8.3](https://github.com/101arrowz/fflate) is MIT and supports streaming raw inflation without a separate process or Python runtime. It is dynamically imported only for deflated Word archives. Native compression streams would avoid a library but would exclude older system WebViews: [WebKit introduced Compression Streams in Safari 16.4](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/), while the project supports older macOS versions. ZIP validation follows the [PKWARE ZIP specification](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT); the PDF streaming API was verified against the installed, patched PDF.js 6.2.108 code. File extraction remains local throughout.

The audit does not measure app rendering, autosave, the operating system's file cache or a user-managed model server. Workspace-wide storage limits and editor scheduling are separate controls. No model helper was started or restarted for this work.

## Word counting on body edits

A later diagnostic found that `wordCount` created an array and substring for every word through `text.trim().match(/\S+/gu)`. The footer now counts whitespace-to-word transitions with one scan and constant working memory. Its whitespace rules preserve ECMAScript `\s`, including Unicode spaces, the BOM, and line separators. An independent regex oracle verifies every UTF-16 code unit, mixed text, surrogate boundaries, long words, and non-whitespace characters such as the next-line control and zero-width space. The scanner remains linear in note length; it does not introduce a cache or retain note text.

`node --expose-gc tests/perf/word-count.mjs final` compares the actual current function with the former regex on synthetic fixtures and writes only ignored JSON under `artifacts/service-benchmark/`. Node 24.17.0 on the same Windows host ran eight warmups and 25 timed calls per algorithm/fixture, with browser tests and compilation paused. The first fixture is the same 1,014,848-character document used by the editor profile. The UTF-8 size of each larger fixture is just below eight MiB.

| Synthetic text                             | Regex median / p95 | Scanner median / p95 |
| ------------------------------------------ | -----------------: | -------------------: |
| Same editor fixture, 1,014,848 ASCII bytes |   3.234 / 7.334 ms |     1.999 / 2.379 ms |
| Near eight MiB, 8,387,584 ASCII bytes      | 29.323 / 41.576 ms |   21.326 / 21.760 ms |
| Unicode spaces, 1,048,512 UTF-8 bytes      |   4.263 / 4.704 ms |     1.848 / 1.891 ms |
| Unicode spaces, 8,387,580 UTF-8 bytes      | 40.339 / 47.455 ms |   14.327 / 14.795 ms |

Single-call heap snapshots before explicit collection grew by 8,376,264 and 66,163,008 bytes for the two ASCII regex cases, versus 10,416 and 7,144 bytes for the scanner. These are allocation diagnostics including measurement overhead, not total allocated bytes or retained-memory measurements. After explicit collection, both methods were within roughly 5–8 KiB of the preceding reading. During the 25-call ASCII timing windows, the regex produced six and 18 automatic GC events; the scanner produced none. All four scanner timing windows had no automatic GC events.

This provides evidence for reducing temporary allocations and word-count CPU cost. It does not establish a desktop RAM limit or an end-to-end typing latency gain; browser interaction measurements are documented separately in `docs/editor-resource-audit.md`.

## Context library migration

Reusable context stores each imported snapshot once in a library capped at 2,048 items. Notes retain lightweight references to it. Migrating older per-note sources must also preserve unmatched text when the library is full. The former migration searched the library linearly for each legacy source, including sources it could no longer promote at the cap.

Migration now checks source IDs directly and lazily builds compact fingerprint buckets for snapshot lookup. A fingerprint match is always followed by a full metadata/text equality check, so differing bodies and hash collisions cannot overwrite a reference. Live-note entries match by their linked note ID. The migration copies arrays only when a source is actually promoted; already-migrated inputs return without building the lookup, and a full library leaves unmatched legacy sources intact.

The helper-only synthetic fixture contains 2,048 canonical entries and 40,000 unmatched legacy references across 157 notes: 156 notes contain 256 sources each, and the final note contains 64. These counts respect the per-note source cap, but the fixture is not a complete validated or imported workspace. Serializing only its notes and library produces 5,193,887 bytes, about 5.19 MB. Bodies are short synthetic strings, with no user text, model process, network request or browser involved.

On the same Windows/Node host, one warmup preceded five timed calls, with explicit collection before each call. Each call verified that both result arrays were the exact input arrays and that the unmatched references remained present.

| Migration of the same synthetic inputs |    Median |  Minimum / maximum |
| -------------------------------------- | --------: | -----------------: |
| Linear snapshot lookup                 | 687.82 ms | 628.15 / 793.89 ms |
| ID lookup and fingerprint buckets      |  27.96 ms |   27.29 / 32.47 ms |

The ignored local harness is `artifacts/context-library-migration.mjs`; `node --expose-gc artifacts/context-library-migration.mjs after` transpiles and imports the actual helper with the installed TypeScript dependency. The earlier sample used the same harness before the lookup change. Regression tests cover equal snapshots with different IDs, same-ID snapshots with different bodies, live-note deduplication, and preservation at the cap.

These five warm-process samples show the reduced lookup cost for this fixture. They do not measure retained heap, JSON validation, disk I/O, rendering or total startup time, and they do not establish a timing guarantee for every source distribution. Fingerprinting still scans previously unseen snapshot text, and equality checks still compare candidates within a matching bucket.

The library dialog stays mounted for its modal lifecycle, but its closed state returns stable empty collections for folder, usage, note, search, attachment and picker calculations. Typing elsewhere therefore does not scan all notes or references through the hidden dialog. Reopening calculates current selections and live titles from the latest inputs. A regression observes zero helper calls and zero note/source lookup reads across closed writing renders and closing an active note picker.

Context resolution returns the original note when it has no sources or only ordinary snapshots. Canonical ID lookups are built only for library references and cached with weak keys on immutable library arrays; replaced snapshots receive a new index, and unused arrays can be collected. Linked-note indexes are built only when needed, remain local to one resolution call, and read current target writing. No additional note-body cache is kept globally. Tests verify reuse across writing edits, same-ID snapshot replacement, missing canonical entries and current linked titles/text with an unchanged canonical library.
